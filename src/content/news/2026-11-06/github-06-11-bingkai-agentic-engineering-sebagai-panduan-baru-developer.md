Dalam tulisan di blog resminya, GitHub (06/11) memperkenalkan kerangka kerja bernama agentic engineering sebagai panduan bagi developer dalam memanfaatkan GitHub Copilot di empat tahap pekerjaan: perencanaan, penulisan kode, peninjauan perubahan, dan investigasi masalah pada sistem yang sudah berjalan. Pesan utama yang diangkat GitHub sederhana: menulis kode kini terasa lebih cepat, tetapi pekerjaan di sekitarnya belum ikut otomatis.

GitHub membagi alur kerja tersebut ke dalam empat peran Copilot yang dapat dijalankan secara bergantian. Pada tahap perencanaan, Copilot dipakai untuk memecah tugas menjadi langkah-langkah kecil dan menyusun rencana implementasi. Saat penulisan kode, Copilot menghasilkan draf kode berdasarkan konteks yang tersedia. Pada tahap peninjauan, Copilot membantu membaca perubahan, menandai potensi masalah, dan menyiapkan ringkasan untuk ditinjau manusia. Ketika terjadi insiden di produksi, Copilot dapat menelusuri log, menarik informasi relevan, dan merangkum temuan awal. Di setiap tahap, GitHub menekankan bahwa Copilot berperan sebagai asisten, bukan pengganti keputusan developer.

Kerangka ini muncul di tengah makin melekatnya asisten AI ke perangkat kerja developer. Selama beberapa tahun terakhir, perhatian publik banyak tertuju pada kemampuan model menghasilkan kode, mulai dari melengkapi baris hingga membuat fungsi utuh. GitHub lewat panduan ini mencoba menggeser sorotan ke pekerjaan yang biasanya tidak terlihat: memahami permintaan, memikirkan struktur solusi, membaca kode orang lain, dan menanggapi gangguan di sistem yang sudah hidup. Dengan kata lain, agentic engineering membingkai Copilot sebagai rekan kerja yang bisa dilibatkan di sepanjang siklus pengembangan, bukan hanya saat mengetik kode.

Secara umum, istilah agentic merujuk pada kemampuan sistem AI untuk mengambil inisiatif menjalankan beberapa langkah secara berurutan demi mencapai tujuan yang diberikan pengguna, bukan sekadar menjawab satu pertanyaan tunggal. Dalam konteks pengembangan perangkat lunak, pendekatan ini biasanya berarti AI diberi ruang untuk membaca repositori, menjalankan perintah, dan memeriksa hasilnya sebelum menyerahkannya kembali ke manusia. Panduan GitHub (06/11) menegaskan bahwa pada setiap tahap tersebut, penilaian profesional developer tetap menjadi penentu akhir, terutama saat menyangkut keamanan, arsitektur, dan dampak perubahan terhadap pengguna.
